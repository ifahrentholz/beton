Session starten und im Terminal begleiten (mit `-p` nicht-interaktiv)

Usage: beton run [OPTIONS] [TARGET]

Arguments:
  [TARGET]
          Harness, z. B. `claude` (Default: `harnesses.default`, sonst `claude`)

Options:
  -p, --prompt <PROMPT>
          Prompt für den Skript-Modus; `-` liest ihn von stdin

      --server <URL>
          Server-URL statt des lokalen Daemons (Token aus `BETON_TOKEN`)
          
          [env: BETON_SERVER]

      --json
          Maschinenlesbare Ausgabe (JSON) auf stdout

      --model <M>
          Modell (sofern der Harness es unterstützt); mit `-c`/`--resume` ein Wechsel ab dem
          nächsten Turn

      --effort <LEVEL>
          Reasoning-Effort; eine Stufe, die der Harness nicht kennt, wird auf die nächstniedrigere
          gemappt (HAR-017)
          
          [possible values: low, medium, high, xhigh]

  -q, --quiet
          Keine Fortschritts- und Hinweismeldungen auf stderr

      --permission-mode <MODE>
          Wie viel der Agent ohne Rückfrage darf (HAR-027). `yolo` startet nur mit Tool-Sandbox und
          Egress-Proxy

          Possible values:
          - plan:         Nur lesen und planen
          - default:      Standard des Harness; Freigaben laut Policy
          - accept_edits: Datei-Edits im Worktree ohne Rückfrage
          - yolo:         Keine Rückfragen des Agents; nur mit Sandbox und Egress-Proxy

  -v, --verbose...
          Mehr Diagnose auf stderr (mehrfach: noch mehr)

      --cwd <DIR>
          Arbeitsverzeichnis der Session (Default: aktuelles Verzeichnis)

      --no-color
          Keine Farben (auch über `NO_COLOR`)

  -c, --continue
          Zuletzt genutzte Session in diesem Verzeichnis fortsetzen

      --config <FILE>
          User-Konfiguration aus dieser Datei statt `~/.beton/config.yaml`

      --resume <ID>
          Diese Session fortsetzen (ID, Präfix oder `last`)

      --fork <ID[@SEQ]>
          Neue Session ab einem Event dieser Session abzweigen: `ID@SEQ`, ohne `@SEQ` ab dem Ende
          (SES-006). Mitten in einem Turn beginnt der Fork am vorherigen Turn-Ende

      --harness <HARNESS>
          Harness des Forks (wie TARGET); ein anderer Harness bekommt eine Übergabe (SES-007)

      --workspace <MODE>
          Dateien des Forks: neuer Worktree (Default im Git-Repository), gemeinsam oder leer

          Possible values:
          - new-worktree: Neuer `git worktree` vom Stand der Quelle inkl. WIP-Snapshot
          - shared:       Dieselben Dateien wie die Quelle
          - fresh:        Leeres Verzeichnis, nur der Verlauf

      --title <T>
          Titel der neuen Session

      --worktree [<BRANCH>]
          Session in einem eigenen `git worktree` mit eigenem Branch starten (Default-Branch
          `beton/<titel>-<id4>`; ein vorhandener Branch wird ausgecheckt)

      --base <BRANCH>
          Base des Worktrees (Default: `origin/HEAD`, sonst der aktuelle Branch)

      --detach
          Session anlegen, ID ausgeben und nicht anhängen

      --output-format <FORMAT>
          Ausgabe im Skript-Modus

          Possible values:
          - text:        Nur der Antworttext
          - json:        Am Ende genau ein JSON-Objekt
          - stream-json: NDJSON der Events
          
          [default: text]

      --on-ask <MODE>
          Verhalten bei Freigaben ohne Terminal: warten (Web-UI) oder sofort ablehnen
          
          [default: wait]
          [possible values: wait, deny]

      --timeout <DUR>
          Abbruch nach dieser Dauer, z. B. `90s`, `5m` (Skript-Modus)

      --scenario <FILE>
          Szenario-Datei, nur für den Harness `fake` (HAR-026)

  -h, --help
          Print help (see a summary with '-h')

  -V, --version
          Print version
