Sandbox: Fähigkeiten der Backends prüfen und die aufgelöste Sandbox anzeigen

Usage: beton sandbox [OPTIONS] <COMMAND>

Commands:
  probe    Alle Sandbox-Backends dieses Rechners mit ihren Fähigkeiten und je fehlender Fähigkeit
           dem Grund (ändert nichts)
  explain  Die aufgelöste Sandbox für das aktuelle Verzeichnis: Wurzeln, Masken, Netz, Regeln und
           die Namen der Environment-Variablen (nie ihre Werte)
  exec     Ein Kommando von Hand in der Sandbox einer Stufe ausführen (ohne Netz): z. B. `beton
           sandbox exec --stage tools -- cat ~/.ssh/config` scheitert. Ein Kommando, das scheitert,
           endet mit Exit-Code 1 und einem Hinweis auf `beton sandbox explain`
  test     Selbsttests der Sandbox-Backends dieser Plattform (die Fälle der Probe) ausführen.
           Pflicht ist das Backend, das eine Session hier nähme (`sandbox.backend`, sonst `auto`);
           Exit 0 nur, wenn es bestanden hat. Die vollständige Escape-Suite läuft als Tests aus dem
           Quellbaum (SBX-011)

Options:
      --server <URL>
          Server-URL statt des lokalen Daemons (Token aus `BETON_TOKEN`)
          
          [env: BETON_SERVER]

      --json
          Maschinenlesbare Ausgabe (JSON) auf stdout

  -q, --quiet
          Keine Fortschritts- und Hinweismeldungen auf stderr

  -v, --verbose...
          Mehr Diagnose auf stderr (mehrfach: noch mehr)

      --no-color
          Keine Farben (auch über `NO_COLOR`)

      --config <FILE>
          User-Konfiguration aus dieser Datei statt `~/.beton/config.yaml`

  -h, --help
          Print help

  -V, --version
          Print version
