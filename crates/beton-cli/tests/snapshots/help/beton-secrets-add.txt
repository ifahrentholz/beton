Secret anlegen; den Wert verdeckt am Terminal eingeben, über `--stdin` oder `--from-file`, nie als
Argument

Usage: beton secrets add [OPTIONS] <TARGET>

Arguments:
  <TARGET>
          Provider (`github`, `gitlab`, `openai`, `anthropic`, `npm`, ein Host wie
          `gitlab.example.com` oder `custom:<name>`) oder eine vollständige SecretRef
          (`secret://user/<provider>/<account>[#name]`)

Options:
      --account <ACCOUNT>
          Account beim Provider (Default `default`)

      --server <URL>
          Server-URL statt des lokalen Daemons (Token aus `BETON_TOKEN`)
          
          [env: BETON_SERVER]

      --json
          Maschinenlesbare Ausgabe (JSON) auf stdout

      --name <NAME>
          Zusätzlicher Name, falls es mehrere Secrets je Account gibt

  -q, --quiet
          Keine Fortschritts- und Hinweismeldungen auf stderr

      --type <KIND>
          Art des Secrets

          Possible values:
          - token: Ein Token, z. B. API-Key oder PAT
          - basic: User und Passwort (`--username`; der Wert ist das Passwort)
          - oauth: OAuth-Token als JSON mit `access_token`
          
          [default: token]

      --username <USER>
          Benutzername für `--type basic`

  -v, --verbose...
          Mehr Diagnose auf stderr (mehrfach: noch mehr)

      --no-color
          Keine Farben (auch über `NO_COLOR`)

      --stdin
          Wert von stdin lesen (ohne abschließenden Zeilenumbruch)

      --config <FILE>
          User-Konfiguration aus dieser Datei statt `~/.beton/config.yaml`

      --from-file <FILE>
          Wert aus dieser Datei lesen

  -h, --help
          Print help (see a summary with '-h')

  -V, --version
          Print version
